## 2. 팀 하드웨어 현황

| 담당 | 로컬 환경 | 비고 |
|---|---|---|
| A | HP 오멘 15, RTX 5060 (8GB, Blackwell) | **팀 내 유일한 자체 NVIDIA GPU**. 사용 제한 없음 → 메인 실험 허브 |
| B | MacBook M3, RAM 16GB | Apple Silicon (MPS만 가능, CUDA 없음) → Colab Pro 활용 예정 |
| C | Intel i9 Mac | 구형, GPU 사실상 없음 → Colab Pro / AWS 혼용 예정 |
| D | (미상) | Colab Pro 사용 예정 |

### 인프라 원칙
- **A의 RTX 5060이 메인 학습 자원** — 무제한·최신 아키텍처·추가비용 없음. 반복 실험(하이퍼파라미터 튜닝, 디버깅)에 최적
- **Colab Pro는 팀원당 1세트 지원**(대회 측 지원, 월 단위 자동갱신 구독, 지원은 1회=1개월치)
  - 4명 각자 자기 명의로 구독 → 계정 공유로 인한 세션 충돌 문제 없음
  - 유닛이 유한하므로 "확정된 최종 학습"에 계획적으로 사용, 반복 실험은 로컬에서 먼저 검증 권장
  - 구독 시작 타이밍은 본격 학습 진입 시점에 맞춰 팀 전체가 조율 (너무 일찍 시작하면 마감 직전 지원 기간이 끝나있을 위험)
  - AWS는 대회 측 지원 대상이 아닐 가능성이 높으므로, 비용 발생 시 팀 내 별도 협의 필요
- **막힌 사람은 A의 GPU를 빌려 쓸 수 있음** (원격 접속 또는 코드 전달)

### 코드 작성 원칙 (환경 혼재 대응)
- CUDA(A 로컬/Colab), MPS(맥북), CPU를 모두 마주치므로 **device-agnostic 코드**로 작성:
  ```python
  device = torch.device(
      "cuda" if torch.cuda.is_available()
      else "mps" if torch.backends.mps.is_available()
      else "cpu"
  )
  ```
- `requirements.txt`는 최종적으로 Colab(Ubuntu, CUDA) 기준으로 통일 — 실제 최종 학습이 Colab에서 이뤄질 가능성이 높으므로, 로컬(맥북/윈도우)은 코드 개발·검증용으로 한정

## 3. 역할별 상세 업무

### A — 인프라 · EDA · 공통 전처리 · 통합 리드

**평상시**
- 데이터 EDA: 파일 매칭 검증, 서울/비서울 필터링, 미션별 라벨 분포 확인, 오디오 기본 속성 확인
- 공통 전처리 파이프라인 설계 및 배포: 오디오 자르기(startAt/endAt), padding/sliding window, MFCC/Mel-spectrogram 추출, 텍스트 추출 유틸
- 여유 인력으로 Mission 2(C) 서포트

**막판 통합 단계**
- 3개 폴더 구조 표준화 검토
- 결과정리 PPT 취합·전체 조립 (12쪽, Mission 1·2·3 모두 포함)

### B — Mission 1 담당 (성별 분류)

- 음성 기반 성별 분류 모델링
- 후보: MFCC/Mel-spectrogram + CNN, 또는 Wav2Vec2/AST 등 end-to-end 음성 모델
- 핵심 이슈: startAt/endAt 기준 발화 길이가 제각각 → padding/sliding window 전처리 실험
- 학습 환경: 주로 Colab Pro

**막판**: Mission1 폴더 최종 점검 — `inference.py` 단일 실행 테스트, pretrained 가중치 로컬 경로 전환·인터넷 차단 테스트, requirements.txt 재현

### C — Mission 2 담당 (화자 분류, 최고난도)

- 순수 음향 정보만으로 신고자 vs 119대원 구분 (텍스트·순서 정보 사용 불가)
- 음향적 특징(피치, 에너지, 스펙트럴 특성, 발화 스타일 등) 탐색 필요
- B와 오디오 전처리 파이프라인 공유하며 협업
- 실험량이 가장 많을 것으로 예상되는 미션 — A의 로컬 GPU 서포트 우선 배정
- 학습 환경: Colab Pro + 필요시 A의 로컬 RTX 5060

**막판**: Mission2 폴더 최종 점검 — 동일 항목(실행 테스트, 로컬화, requirements.txt)

### D — Mission 3 담당 (증상 인식)

- 대화 텍스트 기반 멀티라벨 분류 (9개 증상 클래스)
- 후보: KoBERT, KLUE-BERT 등 한국어 텍스트 모델 fine-tuning
- 핵심 이슈: 클래스 불균형 대응(가중치 손실, threshold 조정 등), Macro F1 최적화
- 학습 환경: Colab Pro (MacBook 로컬 MPS로도 가벼운 실험 가능)

**막판**: Mission3 폴더 최종 점검 — 동일 항목 + **효율성 지표 4종이 3개 미션 모두 빠짐없이 기재됐는지 전체 취합 검증**

## 4. 협업 프로세스 (따로, 그러나 자주 맞춰가기)

각자 미션을 독립적으로 진행하되, 아래 동기화 지점을 통해 포맷 충돌과 중복 시행착오를 방지합니다.

| 단계 | 내용 |
|---|---|
| **1. 킥오프** | 전원 참여 EDA + 공통 규칙 확정 (CSV 형식, 폴더 템플릿, 실험 기록 방식) — A가 초안 작성, 전원 합의 |
| **2. 진행 중** | 각자 미션 작업 + 2~3일마다 진행상황·이슈 짧게 공유 (특히 B-C는 오디오 전처리 이슈를 자주 공유) |
| **3. 중간 지점 (마감 3~4일 전)** | 1차 결과물 완성 후, 서로 다른 사람 코드를 한 번씩 실행해보는 크로스테스트 |
| **4. 막판 통합** | 합의된 포맷대로 각자 폴더 QA + A가 PPT 취합 |
