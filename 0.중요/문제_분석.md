# 문제 분석 — 데이터+AI 크리에이터 캠프 (대학부 예선)

> 이 문서는 프로젝트 루트에 두고 Claude Code가 작업 시 참고하는 컨텍스트 문서로 사용합니다.

## 1. 문제 개요

**주제**: 전화대화 음성 및 전사 데이터를 이용한 응급상황 인식

- **목표**: 음성 및 전사 등 발화 분야의 광범위한 기술 스택을 이용하여 사회안전이라는 문제를 해결
- **데이터셋**: AI-Hub "위급상황 음성/음향(고도화) - 119 지능형 신고접수 음성인식 데이터"
  - 분야: 재난안전환경 / 유형: 오디오, 텍스트
  - 구축년도: 2023 / 용량: 87.29 GB
  - **구글 드라이브로 제공된 데이터만 사용 가능** (AI-Hub 원본 사이트 등 외부 데이터 추가 다운로드 금지)

## 2. 데이터 구성

### 음성 파일 (.wav)
- 신고 유형별 통화 오디오 (예: 구급)
- 한 통화 = 신고자·119대원 발화 모두 포함
- 파일명 = 고유 통화 ID + 날짜

### 전사 및 annotation 파일 (.json)
주요 필드:
```json
{
  "mediaType": "Mobile",
  "gender": "F",
  "address": "서울특별시 서초구 반포동",
  "disasterLarge": "구급",
  "disasterMedium": "질병(중증)",
  "urgencyLevel": "상",
  "sentiment": "당황/난처",
  "symptom": ["경련/발작"],
  "triage": "잠재응급증상"
  // 그 외: startAt, endAt, Speaker, text 등
}
```

## 3. 핵심 제약 조건

### 데이터 사용 범위
- ✅ 구글 드라이브로 제공된 데이터만 사용
- ✅ Training은 서울 데이터만 사용 (address 필드 기준 필터링 필요)
- ❌ AI-Hub 원본 사이트 등 외부 데이터 추가 금지 (동일 데이터셋이라도 제공 경로 외 다운로드 금지)
- ⚠️ 제공받은 데이터 중 각 mission에서 지정하는 입력과 출력만 입력/출력으로 사용 가능 (지정되지 않은 라벨링 데이터를 입력으로 사용 금지)
- ⚠️ Sample instance마다 label에 따라 상이한 전처리 금지
- ⚠️ 평가 데이터에서만 유리한 특별 전처리 금지

### 모델 사용 범위
- ✅ 공개 pre-trained 모델(Hugging Face 등)을 직접 다운로드하여 자체 환경에서 inference/fine-tuning — 허용 (ResNet50, KoBERT, Wav2Vec2, HuBERT, AST 등, LLM 포함)
- ❌ GPT, Claude, Google Vision 등 **상용 AI API를 직접 호출**하는 방식 — 금지
- 판단 기준: "직접 보유한 가중치로 inference냐" vs "외부 API 호출이냐"

### Validation 사용 범위
- ✅ 허용: 모델 구조·하이퍼파라미터 선정, Early Stopping / Best Checkpoint 선정, LR Scheduler 트리거, 최종 모델 선택, 앙상블 가중치 조정
- ❌ 금지(실격 사유): Validation 데이터를 Train Set으로 직접 편입하여 backpropagation에 사용

### 도구 후보 (예시)
KoBERT, MFCC, Mel-spectrogram, Wav2Vec2, AST(Audio Spectrogram Transformer), RandomForest, ResNet

### 음성 처리 가이드 (참고용)
- Raw waveform → librosa 등으로 MFCC 또는 Mel-spectrogram 추출 가능
- 이미지 모델 활용 → MFCC/Mel-spectrogram을 2D 이미지로 취급하면 ResNet, ViT 등 이미지 분류 모델 그대로 적용 가능
- End-to-end → Wav2Vec2, HuBERT, AST 등 음성 특화 모델 fine-tuning 가능
- 어느 경로가 어떤 Mission에 유리한지는 직접 실험 필요

## 4. 3개 미션 상세

### Mission 1 — 신고자의 성별 분류하기
- **문제**: 음성으로부터 신고자의 성별을 분류
- **입력**: 음성(원천데이터)
  - 라벨링데이터는 학습 시 `startAt`, `endAt`, `Speaker`만 사용 가능
  - 추론 시 `startAt`, `endAt`만 사용 가능
- **출력**: 남/여 분류 (라벨링데이터의 `gender`)
- **평가지표**: Accuracy
- **힌트**: 짧은 음성은 padding, 긴 음성은 sliding window(적절한 stride)로 전처리하는 방식이 유용

### Mission 2 — 신고자/119대원 분류하기
- **문제**: 주어진 음성이 신고자의 발화인지 119대원의 발화인지 분류
- **입력**: 한 사람의 한 발화 조각
  - 조각의 기준은 라벨링데이터의 `startAt`, `endAt`으로 정함
  - `startAt`, `endAt` 이외의 annotation 사용 불가 — **text(전사 텍스트)도 사용 불가**
  - 발화의 홀짝 등 순서 사용 불가 (즉 순수 음향 정보만으로 판단해야 함)
- **출력**: 신고자(speaker=1) / 119대원(speaker=0) 분류
- **평가지표**: Accuracy
- **비고**: 참가자는 학습 완료된 모델과 추론 코드를 함께 제출
- **난이도**: 텍스트·순서 정보 없이 순수 음향(피치, 에너지, 스펙트럴 특성, 발화 스타일 등)만으로 화자를 구분해야 해서 3개 미션 중 가장 어려울 것으로 예상

### Mission 3 — 환자의 증상 인식
- **문제**: 대화로부터 환자의 증상을 인식
- **입력**: 신고자 및 119대원의 대화 텍스트(라벨링데이터)
  - 전사 텍스트 외 라벨링데이터 사용 불가
- **출력**: 환자의 증상 (라벨링데이터의 `symptom`)
  - 개수는 0개~9개일 수 있음
  - symptom 클래스는 다음 **9개만 취급**: 고열, 구토, 두통, 복통, 어지러움, 열상, 오심, 전신쇠약, 호흡곤란
  - 데이터의 symptom list에 위 9개 이외 증상이 포함된 경우, 해당 symptom은 평가 대상에서 제외 (전처리 과정에서 symptom list에서 제거하되, **샘플 전체를 제거하는 것이 아니라 target 9개에 해당하지 않는 label만 제외**)
  - symptom 클래스는 string type으로 처리
  - 예시: `Sample 1의 symptom => ['두통', '복통', '찰과상']` → 9개 클래스에 포함되는 `['두통', '복통']`을 string type으로 출력
- **평가지표**: 증상 종류별로 F1-score를 계산한 뒤 평균 (Macro F1)

#### Mission 3 F1-score 계산 예시 (통화 4건, 3종 symptom 기준)
1. 통화별 정답/예측 symptom 정리
2. 레이블별로 이진화 (각 통화에서 그 레이블이 있으면 1)
3. 레이블별로 TP/FP/FN 집계 → Precision, Recall, F1-score 계산
4. Macro 평균 = 각 클래스 F1의 평균

## 5. 최종 평가 방식
- 예선 최종 평가는 Mission 1, Mission 2, Mission 3의 **평가 순위를 합산**하여 진행

## 6. 실행 규칙

- 참가자는 학습 완료된 모델과 추론 코드를 함께 제출
- 평가 시에는 주최 측이 제공하는 Validation 또는 Test 입력 폴더를 대상으로 진행
- 실행 명령 예시:
  ```
  python inference.py --audio_dir {wav folder} --label_dir {json folder} --ckpt_path {checkpoint file} --output ./outputs/mission{미션번호}.csv
  ```
- 명령어를 1회 실행하여 결과 파일을 생성할 수 있어야 함
- 참가자가 내부적으로 전처리, feature 추출, 모델 추론, 후처리 등 여러 단계를 사용하더라도, 최종 실행은 mission별 위 명령어 한 번으로 완료되어야 함
- 출력 파일은 각 Mission별 지정된 CSV 형식에 맞춰 저장:
  - Mission 1 CSV: `[audio file name, startAt, endAt, gender]`
  - Mission 2 CSV: `[audio file name, startAt, endAt, speaker]`
  - Mission 3 CSV: `[label file name, symptom]`

## 7. 제출 파일 안내

- `inference.py` 파일 (위 실행 규칙 조건에 맞아야 함)
- 학습 코드 파일 (학습 로그가 포함된 `.ipynb`)
- 학습 완료된 모델 가중치 파일 (`.pt`, `.pth` 또는 `.ckpt`)
- 모델 코드 파일 (`.py`)
- 필요 패키지 `requirements.txt`
- 결과 정리 PPT — 전반적 미션 수행 내용 포함 (데이터 분석 내용, 모델 설명, 결과 분석, 사회안전 시사점 등)
- ⚠️ 주의: 코드 내 불필요 부분 삭제, 주석 필수

### 제출물 구성 (구체화)
- 정해진 파일명/폴더구조는 없음
- 단, **미션별 코드 폴더 3개** + **미션 1·2·3을 모두 포함한 단일 PPT 1개(12쪽 기준)**로 제출
- 각 폴더는 미션별 `inference.py` 실행 한 번으로 해당 미션의 결과 파일을 생성할 수 있어야 함

## 8. 채점 환경 대응 (FAQ 반영)

- Pre-trained 모델 사용 시, 채점 시점에 인터넷 다운로드에 의존하면 실행 실패 가능성이 있으므로 **tokenizer, config, weight 파일을 제출물에 포함**하거나 **로컬 경로에서 불러오도록** 구성할 것
- `requirements.txt`로 실행 환경을 재현할 수 있어야 함
- `README.md`는 필수는 아니나, 실행 방법을 README 또는 코드 주석으로 명확히 설명하는 것을 권장
- 학습 과정과 주요 실험 결과는 `.ipynb` 또는 PPT에 정리

### 추론 시간 관련 — 미션별 필수 기재 권장 4종
1. 모델의 Total 파라미터 수 및 Active 파라미터 수
2. 학습 및 추론에 사용한 컴퓨팅 환경 (GPU/CPU 종류 등)
3. Validation 추론 시 batch size
4. 해당 환경에서 측정한 Validation 데이터셋 전체 추론시간 또는 샘플당 평균 추론시간

> 팀원마다 하드웨어가 달라도 무방 — 미션 담당자가 실제로 사용한 환경을 그대로 밝히면 됨. 팀 전체가 환경을 통일할 필요는 없음.
